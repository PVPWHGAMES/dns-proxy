## 🎯 开发计划

### 第一阶段：核心功能完善（预计 2-3 周）

#### 1.1 完善 DoT 实现

**目标**：实现完整的 DNS-over-TLS 加密查询

**当前状态**：DoT 协议已枚举，但实现简化为 TCP（未加密）

**实现方案**：
- 使用 `tokio-rustls` 或 `native-tls` 实现 TLS 客户端
- 添加 TLS 证书验证逻辑
- 支持自定义 DoT 端口（默认 853）

**涉及文件**：
- `src-tauri/src/dns/handler.rs` - 转发逻辑
- `src-tauri/src/config.rs` - 配置结构体
- `src-tauri/Cargo.toml` - 添加 TLS 依赖

**验收标准**：
- [x] 能够通过 DoT 协议查询 DNS
- [x] TLS 证书正确验证
- [x] 延迟测试支持 DoT 协议

#### 1.3 缓存优化

**目标**：提升 DNS 缓存的效率和智能化程度

**当前状态**：基础 HashMap 缓存，满时淘汰最旧条目

**实现方案**：
- 实现 LRU（最近最少使用）淘汰策略
- 基于 TTL 的智能过期机制
- 缓存命中率统计
- 支持缓存预热

**涉及文件**：
- `src-tauri/src/dns/cache.rs` - 缓存模块
- `src-tauri/src/dns/handler.rs` - 缓存查询逻辑

**验收标准**：
- [ ] 缓存命中率可查看
- [ ] LRU 淘汰策略生效
- [ ] TTL 过期自动清理

## 📝 注意事项

1. **权限管理**：修改系统 DNS 需要管理员权限，测试时注意权限
2. **端口冲突**：端口 53 可能被其他服务占用，需要检测和释放
3. **防火墙**：TUN 模式需要添加防火墙规则
4. **DNS 泄露**：确保所有请求都经过代理，防止 DNS 泄露
5. **性能目标**：响应延迟 < 10ms（缓存命中），并发 > 1000 QPS
